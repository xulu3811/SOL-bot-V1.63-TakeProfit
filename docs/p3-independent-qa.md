最终结论：已审工程与有限观测范围 PASS，未发现当前未解决的实现阻塞；P3 总体保持 PARTIAL，因为用户指定的 Cursor / Grok 外部审计未完成。本结论不构成实盘许可、长期运行保证或策略盈利证明。

复核日期：2026-11-11。执行者是独立 Codex QA 子代理，没有编写 P3 实现，只新增独立测试、审阅源码并向实现方反馈缺陷。用户指定的 Cursor / Grok 外部审计未执行，不能把本复核标注成这两种审计。QA 未访问服务器、凭证或交易账户；生产事实以主代理提供的脱敏文件为核对范围。

## 独立执行证据

`tests/unit/test_p3_independent_qa.py` 最终 32 项测试全部通过，实际用时 0.562 秒；证据为 `data/p3-independent-local-tests.txt`。执行环境为本地 Python 3.11，使用临时 SQLite 文件，不联网。普通沙盒拒绝启动已安装的 Python 后，使用获准的本地测试执行。重复运行不重复计数。

另外独立重跑其他作者编写的真实回放工具测试 `tests/unit/test_p3_real_replay.py`：9 / 9 PASS，4.677 秒，证据为 `data/p3-replay-independent-rerun.txt`。这 9 项与上述 32 项分别计数，不标注为 QA 自编。复核覆盖 as-of 关联、WAL 冻结、原始源不变、双标的完整 payload 确定性、同计数不同内容的哈希检测、稀疏比较窗口缓存及严格时间边界。

独立参考包括整数分数形式的非十进制 tick / step 向上向下取整、手算微价格与价差 / 不平衡、费用与 EV 算术、Wilder ATR 几何权重参考、仓位风险预算与费用占用，以及 APTS 的边界与持久状态。测试明确区分研究假设、合成证据和实际观测。

覆盖的关键异常：

- 盘口必须完成 snapshot / diff 桥接；旧 update ID 不刷新报价时间，真正缺口失去同步；bookTicker 缺 E 保持未知；倒退的成交时间不能混入窗口。
- 持久化 `ready=true` 不代表永久新鲜。运行消费者重新核验深度、成交和 ticker 的源 / 接收时间；消费者降级保留同步深度供旧保护使用，并保存可重算原始哈希的 `source_snapshot`。
- APTS 初始 0.8% 止损向保护方向取整；1% 进入利润保护，严格大于 1.5% 才进入自适应阶段；止损不降低，先判断旧止损触发，再考虑新的跟踪距离。触发状态重启后保留；完全陈旧数据不伪造成交。
- 新鲜深度在 flow 预热期间仍能触发及执行已有保护 SELL，BUY 保持禁止。单独的 5% 账户锁只禁新买、撤销入场余单，保留仓位和保护；不会仅因该锁自动清仓。
- 部分入场、部分保护退出、现金 / 费用 / 数量及重复深度幂等性；多个订单共享同一份可见流动性，模拟滑点不得突破 LIMIT；主动退出原子取消同仓入场余单。
- 升级保留历史实际成交金额和费用；迁移中途失败回滚扩展字段 / 表 / owner；新实例及已经实例化的旧 writer 均拒绝修改迁移后账本。

## 已关闭的独立发现

实现方修复、独立回归确认的问题包括：成交时间倒退污染窗口；入场未完整校验交易过滤器；迁移使用计划金额而非实际成交金额；完整 flow 预热门槛阻断已有保护；迁移前已实例化对象绕过 owner 初始化检查；部分 BUY 被错误识别为已有 SELL 从而阻止主动退出；持久旧快照导致运行状态误报 ready；消费者修改后未另存原始 hash 对应快照。

这些结论针对当前测试及已审源码。旧 release 已经加载的代码不会获得新 owner 检查，因此部署仍必须先停止旧策略 worker；迁移脚本遵守了该顺序。

初次生产运行另发现旧 P2 调度诊断浮点 score 在新分钟边界导致状态序列化失败；实现方增加仅用于诊断展示的转换。独立新增测试调用真实 `Scheduler.tick` 得到含浮点的实际报告，确认最终状态可写出、原报告未改、金额字符串未改。该新增第 32 项在最终服务代码之后补入测试集，须与服务器部署测试数区别报告。

## 运行桥接与迁移静态复核

`p3_runtime.py` 复用 P2 的闭合 K 线调度与检查点。SOL 仅构造虚拟账本；SUI 使用明确标注的规划余额，不导入或构造真实执行器。缺失实证胜率 / 成本证据时产生 `INSUFFICIENT_EVIDENCE` / `MATH_NOT_APPROVED`，没有为了触发订单而注入虚构证据。数学结果的 `live_authorized` 保持 false。行情健康不可用时仍先处理已有保护。

数学审计以持久 signal identity 去重，压缩保留输入和结果；P2 原始浮点 score 序列化及其哈希保留，数学用副本转为 Decimal 字符串。保护输入含所用闭合 K 线和原始公开快照。内部 CLI / systemd 是运维入口，不是新的远程授权 API；本审查没有把这些内部入口视作具备外部身份验证的服务。

`scripts/p3-migrate.py` 先在线备份并隔离还原，再仅停止两个策略 worker，做最终备份后升级。它逐字段比较原账户 / 订单 / 仓位，核验 LIVE 状态不变；异常分支还原完整账本与旧 unit 并保持 worker 停止。原市场和微结构服务未列为停止目标。下述实际执行记录与脚本边界一致。

真实回放只选 `generated_at <= decision_time` 的持久公开快照，重新验证 payload 哈希、非未来源 / 接收时间以及深度 2 秒、成交 15 秒、ticker 5 秒的边界；没有历史盘口时单独计数不可用。两个独立 replay store 比较完整 decisions / snapshots 和数学输出。真实 close-path 四方案比较仅使用 SOL 闭合 K 线，5 分钟 taker ratio 明确作为代理；未来路径仅用于事后 early-exit 指标，不参与保护决策。
