# SOL-bot 开发准则

## Android 安装包

真实测试使用可安装 APK，不依赖 USB 调试，也不依赖 Android 模拟器。

- 输出目录：`release/`
- 文件名：`SOL-bot vX.XX.apk`
- 当前已发布版本：`SOL-bot v1.51`（后续每次发版版本号递增 `0.01`）
- 设备口令只在第一次绑定时输入。绑定结果保存在本机，之后打开应用自动重连。后台服务监听已接受的策略买入与安全告警信号并发出通知。
- `versionName` 与文件名中的数字一致，不带前缀 v。v1.01 对应 `versionName = "1.01"`。
- `versionCode` 为整数，等于版本号乘以 100。v1.01 是 101，v1.02 是 102。新包的 `versionCode` 必须大于上一包。
- 发布前先查看 `release/` 里已有的最高版本，在该版本上加 0.01，不要重复使用已有版本号。

安装包只用于安装和界面验证。生产 LIVE 保持关闭，APK 不是实盘控制入口。

## 设备绑定

取消一次性配对码，也不再轮换配对码。取消指纹、面容和锁屏凭据认证。连接、刷新、托管和实盘界面操作不再弹出生物识别。

- 首次连接时，用户在手机上填写设备口令。
- 口令与这台手机的设备密钥绑定。服务器只保存口令哈希和设备公钥。
- 设备密钥不要求指纹或锁屏才能签名。
- 同一口令同时只有一台有效设备。再次用这枚口令绑定会替换上一台设备的密钥和会话。
- 绑定成功后会话不过期，手机可以永久连接，并使用客户端已开放的全部功能。
- 用户撤销设备后，该绑定失效。撤销前不需要更换口令。
- 口令不写入 APK，不写入日志。
- 生产 LIVE 仍由服务器门禁控制，绑定成功不等于打开实盘下单。

## P7 本机应用接口

P7 只在服务器本机提供认证后的只读应用接口，地址是 `http://127.0.0.1:8016`。LIVE 开启请求在生产门禁关闭时保持拒绝。

## 回测

实盘和 Shadow 模拟盘都用 BNB 支付现货手续费。回测单边用 0.075%，不用未打折的 0.10%。规则见 [回测准则](回测准则.md)。

## P8 手机 HTTPS 入口

P8 用 Nginx 把公网 443 转到本机 8016。证书只覆盖服务器公网入口 IP，手机安装包只信任这份证书，不关闭证书校验。仅放行 `/healthz` 与 `/api/v1/app/` 路径，其余扫描路径直接返回 `444` 并配合 Fail2Ban 拦截。设备口令哈希放在服务器，不匹配的口令不能绑定。

## P9 运维监控与系统安全审计（`solbot-ops-agent`）

- 运维代理 `solbot-ops-agent.service` 仅监听本机 `AF_UNIX` 套接字（`/run/solbot-ops/ops.sock`），不开放任何 TCP/HTTP 端口，通过内核 `SO_PEERCRED` 仅放行 `solbot-app` 用户调用。
- 严格白名单动作：`system_overview`（CPU/RAM/磁盘及 12 模块健康度）、`optimize_memory`（仅触发 `sync` + `drop_caches=1`，不重启任何交易进程）、`clean_cache_preview` / `clean_cache_execute`（仅清理白名单内旧轮转日志、临时缓存等，绝不触碰数据库与源码目录）以及 `security_logs`（只读返回脱敏后的 SSH/Fail2Ban/API 审计/系统健康日志）。
- 禁止交易执行、风控参数修改或行情抓取路径对运维代理产生任何强依赖；运维代理异常时 App 端优雅降级提示，核心交易系统保持零影响。
