# P5 报告D：Guardian、资产与BNB

P4风险阈值和账本保持不变。新`risk/p5_bridge.py`在Guardian用户进程接收可信执行事件；实际现金、机器人净持仓、余单、费用和审计同事务保存。USDT费用扣现金，SUI费用减少可卖净数量，BNB费用仅从机器人BNB扣除；归属不足保留待结算异常。实际费用超过研究预留也按实际记录并进入待对账，不把真实费用截断为模型值。

手动资产不因余额变化自动变成机器人资产。首次连接需PENDING只读租约、账户权限、主账户可用USDT、按本地clientOrderId和交易所orderId匹配的完整订单/成交、保护和过滤器检查。历史成交分页核对，并比较费币种/数量。手动订单单独记录并保守阻断首次恢复；资金无法归属时保持拒绝。当前生产无任何私有连接，因此2000仍为分配计划，未冒称实有资产。

保护卖单经过持仓数量和独立退出预留核验，普通策略无法使用未授权手动SUI。真实卖出费用、收益与持仓减少接回P4账本。5%硬锁时执行器在有效用户租约内撤机器人入场单并核实终态，保护单保留，不自动全平。OFF撤销内存授权并关闭连接，既有交易所原生保护不被撤销，动态管理暂停。

BNB使用独立补充意图，3/约10/20规则及Guardian资金预留；订单进入统一P5状态机，UNKNOWN不重发，实际成交更新机器人BNB和现金，真实手续费按资产记录。生产BNB和SUI请求均被P6最终发布门阻止。

SOL-shadow继续原P3独立模拟库及2000虚拟资金。`p5_models.OrderView`提供统一状态比较视图，明确SIMULATED与LIVE来源；没有把SOL模拟成交当作SUI交易所成交，也未用跨标的盈亏比较执行器优劣。
