- **Data representation and validation:** fixed SOLUSDT, all five native intervals, UTC millisecond units and interval alignment, consistent OHLC, finite nonnegative quantities, decimal-string prices/volumes, and closed-candle-only writes are checked in code and the recorded model/storage tests. The composite database primary key prevents duplicate candle keys. REST final values are authoritative, and conflicts are audited transactionally rather than silently overwritten by a conflicting WS message.
- **Single writer and cancellation:** database writes, migrations, backup, and close share one asynchronous lock. A cancelled writer waits for its worker operation to finish before releasing that lock. Independent short-lived read connections use read-only mode. Recorded tests cover 50 concurrent write/read tasks, cancellation serialization, transaction rollback, migration compatibility, and online backup restoration.
- **Gap detection and repair design:** the required window begins at UTC midnight 30 complete calendar days before today and includes today's completed candles. Detection compares the aligned expected open-time sequence with durable rows; it includes leading, interior, and trailing holes and does not trust a cursor as proof of completeness. Start/end gap bounds are inclusive candle open times. No missing candles are synthesized. Bounded REST pages, repeat scans, and an explicit no-progress error prevent an empty response from spinning forever. Reconnect and periodic reconciliation request repair.
- **Required gap fields and first discovery:** persisted records expose interval, missing start/end, `detected_at`, `last_checked_at`, and open/resolved status. Checked ranges and cursors are also durable. The active gap API has bounded pagination. Review identified that partial repair reset the first-discovery time of a remaining hole. This is now fixed: replacement fragments inherit the earliest discovery time of overlapping predecessors, while genuinely new disjoint gaps get the current time. Source and regression tests were inspected; both first-discovery regression cases pass in the final deployment-runtime transcript.
- **Unavailable is visible:** health combines collector state, all five stream freshness checks, persisted closed-candle freshness, and database gap counts. Unavailable databases and degraded readiness return HTTP 503; the status endpoint remains readable when the database works but exchange collection is degraded. A fresh process alone does not imply readiness.
- **Request and reconnect controls:** the REST client fixes its official public origin and four-endpoint GET allowlist, disallows redirects and credentials, applies request-weight pacing and bounded transport/429/5xx retries, and honors Retry-After. HTTP 418/451 is terminal for the collector and cancels other collection tasks instead of switching endpoints or proxies. WebSocket buffers and open-candle cache are bounded; interval watchdogs, planned rotation, server-shutdown handling, and cancellation cleanup are present. The final market suite passes injected timeout/503/429, terminal-block, reconnect, watchdog, paging/resume, and cancellation cases. ## DEFERRED — explicit operational limits and recommendations

- **Old unresolved gaps:** preserving unchecked gap portions is correct, but a gap that ages outside the moving 30-day repair window can remain open indefinitely and keep aggregate health degraded. Agree whether to repair older retained history or give such gaps an explicit archived state. Do not silently mark them filled or delete them merely to obtain green health.
- **Gap history semantics:** replacing a partially repaired range currently marks its predecessor record resolved while new open fragments remain. Active state is accurate, but historical consumers should understand this as range replacement. A future explicit superseded state or predecessor linkage would make the audit history less ambiguous.
- **Long-duration behavior:** no 24-hour connection-rotation run, extended soak, network-partition campaign, host/disk-loss restoration, or multi-month disk-growth measurement is established here. Continue observation and retain measured time ranges; do not infer an SLA from the short successful samples.
- **Retention and recovery scope:** candle retention is intentionally not truncated without an agreed policy. Event/health metadata and in-memory caches are bounded. Same-host SQLite backup verifies database consistency but does not protect against loss of the host or disk; off-host backup and its recovery drill remain separate work.

Review conclusion: the final 56 passing tests, corrected review findings, live sample, completed ten-minute observation, actual restarts, and backup restores support the implemented P1 data-only architecture within those tested conditions. This document does not claim unrestricted production readiness or long-term reliability. The separate `docs/p1-qa-final.md` records the additional independent review coordinated by the parent.
