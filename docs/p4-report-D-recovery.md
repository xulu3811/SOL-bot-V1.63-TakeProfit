# P4 报告D：LIVE、BNB与恢复

生产最终 LIVE_OFF，私有调用0、真实订单0。Guardian运行进程使用普通solbot用户，systemd PrivateNetwork、AF_UNIX地址族限制和空能力集；代码不构造交易所私有客户端。现有SOL-shadow继续独立运行。

LIVE授权意图单独持久化。重启时以前的ON/PENDING变为PAUSED，核验时间失效，硬锁保留；P4没有私有适配器，不能伪造重建通过。OFF只禁止新入场，保护责任保存在原仓位记录和待办中，不将其标为已清仓。最终执行门即使被伪造ON也拒绝。

BNB模块按3/10/20规则建立补充候选：可用机器人BNB市值低于3才候选，每次约10（按步长向上取整），持有总值（含锁定BNB）加补充不超过20。核查LIVE、资金、对账新鲜度、交易权限、最小额/步长、未完成意图和硬锁。每个意图唯一；未知提交不释放预留。确定未提交的失败累计3次后拒绝后续自动补充，跨意图ID也不能重置。P4所有候选 live_authorized=false，不提交真实BNB订单；未核实折扣时使用保守0.1%费率。

APTS历史语义通过 `risk/apts_compat.py` 显式衔接：保留旧 `APTSParameters.NOT_IMPLEMENTED` 合同供P2回归，单独返回P3数学已实现、P5原生保护未验收。自适应边界为严格大于1.5%，没有擅改现有数学和风险合同。

恢复顺序：停止Guardian；SQLite backup保存一致副本；隔离还原并检查integrity及完整SQL逻辑哈希；核对资金、预留、仓位、硬锁和原LIVE状态；使用相同P4schema与版本恢复；重启仍待核验。不要用P3引擎打开P4账本或将旧备份覆盖有新成交的账本。无人工批准不得执行解锁。

最终真实重启验证资金字段保持一致，已有六个P3服务PID未改变。生产当前空仓；非空仓、未知订单、部分成交和保护保留的验证来自隔离测试，不能当作已完成真实订单恢复。
